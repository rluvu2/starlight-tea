# 별빛 찻집 (Starlight Teahouse)

지친 손님의 사연을 듣고 아홉 가지 재료 중 마음에 맞는 차를 우려 건네는 모바일 힐링 스토리 게임입니다.
내 고민을 적으면 브라우저 안의 작은 언어 분류기가 읽고, 팽주가 어울리는 차를 권해 줍니다.
백엔드 서버 없이 동작하며 GitHub Pages(커스텀 도메인)에 정적으로 배포합니다.

---

## 1. 실행하기

[nodejs.org](https://nodejs.org)에서 **LTS** 버전을 설치한 뒤 (Windows: `winget install OpenJS.NodeJS.LTS`)

```bash
npm install      # 처음 한 번
npm run dev      # 개발 서버 → http://localhost:5173
npm run build    # 데이터 검사 후 dist/ 생성
npm run preview  # 빌드 결과 미리보기
npm run check    # 기획 데이터·배포 설정만 검사
```
휴대폰으로 볼 때는 PC와 같은 와이파이에 연결하고, 터미널에 나오는 `Network: http://192.168.x.x:5173` 주소로 접속합니다.

## 2. GitHub Pages + 커스텀 도메인 배포

배포 설정은 프로젝트 루트의 **`.env`** 한 곳에서 합니다. (공개돼도 괜찮은 값만 들어갑니다)

```ini
BASE_PATH=/                         # 커스텀 도메인 기준. 도메인 연결 전 시험할 때만 /저장소이름/
CUSTOM_DOMAIN=starlight-teahouse.com   # 적으면 빌드 결과에 CNAME 파일 생성
VITE_ADSENSE_CLIENT=ca-pub-1234567890123456   # AdSense 승인 후 입력 (비워 두면 광고 없음)
```

1. GitHub에 저장소를 만들고 이 폴더를 `main` 브랜치로 올립니다.
2. 저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로 바꿉니다. 이후 `main`에 올릴 때마다 `.github/workflows/deploy.yml`이 검사·빌드·배포를 자동으로 합니다.
3. 도메인 연결 전 `https://아이디.github.io/저장소이름/`에서 먼저 시험하려면 `.env`의 `BASE_PATH=/저장소이름/`로 올려 확인한 뒤 `/`로 되돌립니다.
4. 커스텀 도메인:
   - **Settings → Pages → Custom domain**에 도메인을 적습니다.
   - 도메인 업체의 DNS에 GitHub Pages 주소를 연결합니다. (루트 도메인은 A 레코드, `www`는 CNAME. 안내: [GitHub 문서](https://docs.github.com/pages/configuring-a-custom-domain-for-your-github-pages-site))
   - 연결되면 **Enforce HTTPS**를 켭니다.
   - GitHub Actions로 배포할 때는 설정 화면의 도메인이 기준이고, `CNAME` 파일은 다른 배포 방식을 위한 예비용입니다.

**404 방지:** `react-router-dom` 없이 `App.jsx`가 상태(phase)로 화면을 바꾸므로 주소가 바뀌지 않습니다. 빌드할 때 `404.html`(= `index.html`)도 자동으로 만들어, 어떤 주소로 들어와도 게임이 열립니다.

## 3. 수익 모델 — 보상형 광고 (Google H5 Games Ads)

'나를 위한 차 끓이기'를 마치면 **차 우리는 시간(Phase 3.5)** 이 나옵니다. 여기서 유저가 **[광고 보고 조언 듣기]** 를 직접 눌렀을 때만 보상형 광고(`type: 'reward'`)를 요청합니다.

| 광고 결과 | 처리 |
|---|---|
| 끝까지 시청 (`adViewed`) | 팽주의 조언(Phase 4)으로 |
| 중간에 닫음 (`adDismissed`) | "차가 아직 덜 우러났어요." 와 함께 버튼을 다시 보여 줌 |
| 재고 없음·로드 실패·광고 차단기·오류 | 기다리게 하지 않고 바로 조언으로 |
| 8초 동안 아무 응답 없음 | 바로 조언으로 (스크립트가 멈춰도 막히지 않음) |

- 광고가 재생되는 동안 배경 음악과 효과음을 멈추고, 끝나면 다시 켭니다.
- 손님 맞이(Phase 1)와 교차로(Phase 2)에는 광고가 없습니다. 자동 재생, 전면 광고, 배너도 없습니다.
- 광고 버튼 위에 "광고를 보면 팽주의 조언을 들을 수 있어요"라는 보상 안내가 함께 나옵니다.

**준비 순서:**
1. AdSense 가입·승인
2. 커스텀 도메인을 사이트로 등록
3. H5 Games Ads 별도 신청·승인
4. `.env`의 `VITE_ADSENSE_CLIENT`에 게시자 ID를 적습니다. 그러면 `index.html`의 광고 스니펫이 들어가고 `ads.txt`의 게시자 ID도 자동으로 채워집니다.

- 개발 서버(`npm run dev`)에서는 `data-adbreak-test="on"` **테스트 광고**가 나옵니다. 배포 빌드에서는 이 속성이 **자동으로 제거**됩니다.
- 게시자 ID가 비어 있으면 광고 스크립트를 넣지 않습니다. 버튼은 "조언 듣기"로 바뀌고 광고 없이 조언이 열립니다. (승인 전에도 게임은 그대로 동작)
- 유럽 등 동의가 필요한 지역의 유저에게는 AdSense 콘솔의 **개인정보 보호 및 메시지**에서 동의 메시지를 켜 주세요.

**AdSense 심사용 페이지:**
- `public/about.html`(게임 소개)과 `public/privacy.html`(개인정보처리방침, 광고 쿠키 고지 포함)이 있습니다.
- 타이틀 화면 아래와 설정 창에서 연결됩니다.
- **배포 전에 두 파일의 `[운영자 이름]`, `[문의 이메일]` 빈칸을 채워 주세요.** 빈칸이 남아 있으면 `npm run check`가 알려 줍니다.

## 4. 기획자 가이드 (코드 수정 없음)

### 손님 추가 — `src/data/guests.js`
`GUESTS` 배열에 블록 하나를 복사-붙여넣기 하면 손님 도감과 랜덤 방문에 바로 반영됩니다.
```javascript
  {
    id: "guest_004",                 // 고유 ID — 절대 중복 금지 (도감 저장 키)
    name: "길을 잃은 여우",
    appearance: "fox_lost.png",      // public/assets/guests/ 안의 그림 파일명
    story: "손님이 털어놓는 사연",
    required_ingredient: 1,          // 정답 재료 ID (아래 표)
    perfect_match_dialogue: "정답 차를 마셨을 때의 대사"
  },
```
- 랜덤 방문은 `GUESTS.length`를 기준으로 동적으로 고릅니다. 처음 오는 손님이 먼저 오고, 직전 손님은 연달아 오지 않습니다.
- 손님을 추가하거나 빼고 다시 배포해도 기존 유저의 세이브는 깨지지 않습니다. 앱을 열 때 기존 기록과 새 데이터를 안전하게 병합합니다. 새 손님은 도감에 잠긴 채로 나오고, 빠진 손님의 기록은 지우지 않고 보관합니다.

| ID | 열매 | 재료 | ID | 열매 | 재료 | ID | 열매 | 재료 |
|---|---|---|---|---|---|---|---|---|
| 1 | 사랑 | 장미 | 4 | 오래 참음 | 대추 | 7 | 충성 | 솔잎 |
| 2 | 희락 | 유자 | 5 | 자비 | 생강 | 8 | 온유 | 복숭아 |
| 3 | 화평 | 캐모마일 | 6 | 양선 | 꿀 | 9 | 절제 | 박하 |

### 손님 그림
- 위치는 `public/assets/guests/`이고, 파일명은 `appearance` 값과 똑같이 맞춥니다.
- 권장 규격은 정사각형 PNG, 투명 배경, 768px 이상입니다. 머리부터 가슴까지 보이는 상반신 구도로 그려 주세요. 아래쪽 약 20%는 카운터에 가려집니다.
- 그림이 없으면 게임에서는 실루엣으로 나옵니다.
- **[선택]** 같은 폴더에 `_happy`를 붙인 그림(예: `fox_lost_happy.png`)을 두면, 정답 차를 마신 뒤 그 표정으로 바뀌고 도감에도 그 표정으로 나옵니다.

### 팽주의 학습 문장 — `src/data/trainData.js`
- 고민 문장을 재료 번호별로 적습니다. 문장을 추가하면 다음 실행부터 바로 학습에 반영됩니다. 별도 학습 도구는 필요 없습니다.
- 속성마다 50문장 이상을 권장합니다. 지금은 속성마다 55문장, 모두 495문장입니다.
- 유저가 실제로 쓸 법한 반말·줄임말·다른 표현을 넣을수록 정확해집니다. (예: "싸워서"와 "다투셔서"는 다른 단어로 봅니다)
- "화가 나는 건 아니에요 그냥 외로워요"처럼 부정이 들어간 문장도 섞어 두면 오판이 줄어듭니다.

### 그 밖의 데이터
| 파일 | 내용 |
|---|---|
| `src/data/ingredients.js` | 재료 이름·설명·찻물 색, 오답 귀띔(`hint`), 팽주의 위로 글귀(`comforts`) |
| `src/data/scripts.js` | 인트로, 교차로·광고 대기·조언 화면의 문구. `{name}`과 조사(`{이/가}` 등)는 자동 처리 |
| `src/data/rewards.js` | 별조각 보상 (정답마다 +1, 손님을 처음 위로하면 +2 추가) |

## 5. 게임 흐름 (`src/hooks/useGameState.js`)

```
TITLE ─(첫 방문)→ INTRO ─→ Phase 1 손님 맞이 ─정답 후 화면 터치→ Phase 2 교차로
Phase 2 ─[다음 손님 맞이하기]→ Phase 1 (새 손님)
Phase 2 ─[나를 위한 차 끓이기]→ Phase 3 고민 쓰기 ─[완성하기]→ Phase 3.5 차 우리는 시간
Phase 3.5 ─광고 시청 / 광고 없음·차단→ Phase 4 팽주의 조언 ─화면 터치→ Phase 2
```
- **Phase 1:** 재료를 고르고 [차 내어주기]를 누릅니다. 정답이면 고유 위로 대사와 별조각이 나오고 도감이 해금됩니다. 오답이면 범용 대사 뒤에 다시 고르고, 두 번째 오답부터 팽주의 귀띔이 나옵니다.
- **Phase 3:** [완성하기]를 누르는 순간 분석을 미리 끝내 둡니다. 그래서 광고가 끝난 뒤 기다림이 없습니다. 고민 글은 분석 직후 지워지고 어디에도 저장하지 않습니다.
- **저장:** 보유 별조각, 해금 도감, 방문 기록, 설정은 바뀔 때마다 `localStorage`에 자동 저장됩니다. 손상된 기록은 따로 보관하고 새로 시작합니다. 이전 버전 기록은 옮겨 오고, 이미 위로한 손님만큼 별조각도 챙겨 줍니다.

## 6. 기술 구성

| 항목 | 사용 |
|---|---|
| 프레임워크 | React 19 + Vite 8 (라우터 없음) |
| 상태 | **React Context + `useReducer`** (외부 상태 라이브러리 없음) |
| 스타일 | Tailwind CSS 4 (`env(safe-area-inset-*)` → `pt-safe`, `pb-safe` 등) |
| 애니메이션 | Framer Motion — `LazyMotion` + `m`으로 필요한 기능만 |
| NLP | 직접 만든 나이브 베이즈 (`src/utils/naiveBayes.js`) |
| 광고 | Google H5 Games Ads (`src/utils/adService.js`) |
| 사운드 | Web Audio API로 로파이 피아노 BGM과 효과음을 실시간 합성 (음원 파일 없음) |

- 첫 화면 JS는 gzip 약 127KB입니다. 팽주의 분석 모듈(학습 문장 포함, 약 11KB)은 '나를 위한 차' 단계에 들어갈 때 따로 받습니다. 학습 문장을 늘려도 첫 화면은 무거워지지 않습니다.
- 모바일 최적화:
  - `overscroll-behavior-y: none`, 세로 `100dvh`, 명세의 viewport 메타 태그
  - iOS 핀치 확대 차단, 고민 입력창 16px(아이폰 자동 확대 방지)

```
src/
  hooks/useGameState.js     ← 상태 머신 + localStorage 안전 병합 (Step 1)
  utils/naiveBayes.js       ← 부정어 전처리 포함 분류기 (Step 1)
  utils/adService.js        ← 보상형 광고, 차단·미송출 방어 (Step 1)
  data/                     ← 기획 데이터 (guests, ingredients, trainData, scripts, rewards)
  logic/                    ← 데이터 검증, 랜덤 방문, 팽주의 조언, 조사 처리
  screens/phases/           ← Phase 1·2·3·3.5·4 화면
  components/               ← 상단 바, 재료 패널, 밤하늘, 찻집 소품 등
  audio/                    ← 음악·효과음 합성
public/                     ← 그림, about.html, privacy.html, ads.txt, manifest
assets-src/                 ← 그림 원본(SVG)
vite.config.js              ← base 전환, 광고 스니펫, 404.html·CNAME·ads.txt (Step 1)
```

## 7. 팽주의 마음 읽기 — 성능

| 평가 | 결과 |
|---|---|
| 학습 문장 5겹 교차 검증 (짧은 문장) | 1순위 51%, 상위 2개 69% |
| 문체가 다른 새 문장 36개 (반말·신조어) | 1순위 81%, 상위 2개 86% |
| 부정어 사례 ("화가 안 나요" 등) | 5/5 |

- 9가지 중 우연히 맞힐 확률은 11%입니다.
- fastText 방식(글자 n-gram 임베딩)도 같은 데이터로 비교했지만 정확도가 같거나 낮았고, 400KB~900KB의 모델 다운로드가 필요해서 채택하지 않았습니다.
- 틀리는 경우는 대부분 학습 문장에 없는 표현입니다. **학습 문장을 늘리는 것이 가장 효과적인 개선 방법입니다.**
- 단서를 전혀 찾지 못하면, 팽주는 유저가 고른 차를 그대로 존중합니다.

## 8. 알려진 한계
- **진동:** 안드로이드는 지원합니다. iPhone Safari는 웹 진동을 공식 지원하지 않아 iOS 18 이상에서만 우회 방식으로 일부 동작합니다.
- **소리:** 브라우저 정책상 첫 터치 이후부터 나옵니다. iPhone 무음 모드에서는 나지 않습니다.
- **광고:** 승인 전에는 실제 광고가 나오지 않으며, 웹 게임 광고는 재고가 없을 때가 많습니다. 그때는 광고 없이 조언이 열립니다.
- **오프라인:** 지원하지 않습니다. 가볍게 유지하려고 서비스 워커를 넣지 않았습니다. 홈 화면 추가(manifest)는 됩니다.
- **저장:** 기록은 기기·브라우저마다 따로 저장되며, 브라우저 데이터를 지우면 사라집니다.
