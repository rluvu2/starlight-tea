# 별빛 찻집 (Starlight Teahouse)

지친 손님의 사연을 듣고 마음에 맞는 차를 우려 건네는 모바일 힐링 스토리 게임입니다.
내 고민을 적으면 브라우저 안의 작은 언어 분류기가 읽고, 팽주가 **찻잎과 과일을 블렌딩한 차**(81가지)를 권해 줍니다.
백엔드 서버 없이 동작하며 GitHub Pages에 정적으로 배포합니다.

**플레이:** https://rluvu2.github.io/starlight-tea/

---

## 1. 실행하기

[nodejs.org](https://nodejs.org)에서 **LTS** 버전을 설치한 뒤 (Windows: `winget install OpenJS.NodeJS.LTS`)

```bash
npm install      # 처음 한 번
npm run dev      # 개발 서버 → http://localhost:5173
npm run build    # 데이터 검사 후 dist/ 생성
npm run preview  # 빌드 결과 미리보기 → http://localhost:4173/starlight-tea/
npm run check    # 기획 데이터·배포 설정만 검사
npm test         # 상태 머신·블렌딩·조언·세이브·광고 단위 테스트 (배포 전에 자동으로도 실행)
```
휴대폰으로 볼 때는 PC와 같은 와이파이에 연결하고, 터미널에 나오는 `Network: http://192.168.x.x:5173` 주소로 접속합니다.

## 2. 배포 (GitHub Pages)

`main` 브랜치에 올리면 `.github/workflows/deploy.yml`이 **데이터 검사 → 빌드 → 배포**를 자동으로 합니다. (저장소 **Settings → Pages → Source = GitHub Actions**)

배포 설정은 프로젝트 루트의 **`.env`** 한 곳에서 합니다. (공개돼도 괜찮은 값만 들어갑니다)

```ini
BASE_PATH=/starlight-tea/                       # 지금: https://rluvu2.github.io/starlight-tea/
SITE_URL=https://rluvu2.github.io/starlight-tea/  # 링크 미리보기 썸네일의 절대 주소
CUSTOM_DOMAIN=                                  # 적으면 빌드 결과에 CNAME 파일 생성
VITE_ADSENSE_CLIENT=                            # AdSense 승인 후 입력 (비워 두면 광고 없음)
```

**커스텀 도메인으로 옮길 때** (AdSense 승인에 필요)
1. **Settings → Pages → Custom domain**에 도메인을 적고, 도메인 업체의 DNS를 GitHub Pages에 연결합니다. (루트 도메인은 A 레코드, `www`는 CNAME. 안내: [GitHub 문서](https://docs.github.com/pages/configuring-a-custom-domain-for-your-github-pages-site))
2. `.env`를 `BASE_PATH=/`, `SITE_URL=https://내도메인/`, `CUSTOM_DOMAIN=내도메인`으로 바꿔 올립니다.
3. 연결되면 **Enforce HTTPS**를 켭니다.

- **404 방지:** `react-router-dom` 없이 `App.jsx`가 상태(phase)로 화면을 바꾸므로 주소가 바뀌지 않습니다. 빌드할 때 `404.html`(= `index.html`)도 만들어, 어떤 주소로 들어와도 게임이 열립니다.
- **링크 미리보기:** `public/og-image.png`(1200×630)가 카카오톡·SNS 썸네일로 쓰입니다. `SITE_URL`이 비어 있으면 GitHub Actions에서 `아이디.github.io/저장소/` 주소로 자동으로 채웁니다.

## 3. 수익 모델 — 보상형 광고 (Google H5 Games Ads)

'나를 위한 차 끓이기'를 마치면 **차 우리는 시간(Phase 3.5)** 이 나옵니다. 여기서 유저가 **[광고 보고 조언 듣기]** 를 직접 눌렀을 때만 보상형 광고(`type: 'reward'`)를 요청합니다.

| 광고 결과 | 처리 |
|---|---|
| 끝까지 시청 (`adViewed`) | 팽주의 조언(Phase 4)으로 |
| 중간에 닫음 (`adDismissed`) | "차가 아직 덜 우러났어요." 와 함께 버튼을 다시 보여 줌 |
| 재고 없음·로드 실패·광고 차단기·오류 | 기다리게 하지 않고 바로 조언으로 |
| 8초 동안 아무 응답 없음 | 바로 조언으로 (스크립트가 멈춰도 막히지 않음) |

- 광고가 재생되는 동안 배경 음악과 효과음을 멈추고, 끝나면 다시 켭니다.
- 손님 맞이(Phase 1)와 찻집 로비(Phase 2)에는 광고가 없습니다. 자동 재생, 전면 광고, 배너도 없습니다.
- 광고 버튼 위에 "광고를 보면 팽주의 조언을 들을 수 있어요"라는 보상 안내가 함께 나옵니다.

**준비 순서:** AdSense 가입·승인 → 커스텀 도메인을 사이트로 등록 → H5 Games Ads 별도 신청·승인 → `.env`의 `VITE_ADSENSE_CLIENT`에 게시자 ID 입력. 그러면 `index.html`의 광고 스니펫이 들어가고 `ads.txt`의 게시자 ID도 자동으로 채워집니다.

- 개발 서버(`npm run dev`)에서는 `data-adbreak-test="on"` **테스트 광고**가 나오고, 배포 빌드에서는 이 속성이 **자동으로 제거**됩니다.
- 게시자 ID가 비어 있으면(지금 상태) 광고 스크립트를 넣지 않습니다. 버튼은 "조언 듣기"로 바뀌고 광고 없이 조언이 열립니다.
- 유럽 등 동의가 필요한 지역의 유저에게는 AdSense 콘솔의 **개인정보 보호 및 메시지**에서 동의 메시지를 켜 주세요.
- **AdSense 심사용 페이지:** `public/about.html`(게임 소개)과 `public/privacy.html`(개인정보처리방침, 광고 쿠키 고지 포함). **배포 전에 두 파일의 `[운영자 이름]`, `[문의 이메일]` 빈칸을 채워 주세요.** 빈칸이 남아 있으면 `npm run check`가 알려 줍니다.

## 4. 기획자 가이드 (코드 수정 없음)

### 열매 · 찻잎 · 과일 — `src/data/ingredients.js` (재료 ID 고정, 변경 금지)

| ID | 열매 | 찻잎 (1위일 때) | 과일 (2위일 때) | 연결 이미지 |
|---|---|---|---|---|
| 1 | 사랑 | 홍차 | 딸기 | 따뜻하고 붉은 마음 |
| 2 | 희락 | 백차 | 오렌지 | 가볍고 환한 기쁨 |
| 3 | 화평 | 캐모마일 | 복숭아 | 마음을 가라앉히는 부드러움 |
| 4 | 오래 참음 | 보이차 | 대추 | 오랜 시간 숙성되는 깊이 |
| 5 | 자비 | 루이보스 | 무화과 | 감싸 안는 포근함 |
| 6 | 양선 | 녹차 | 청포도 | 맑고 곧은 선함 |
| 7 | 충성 | 우롱차 | 석류 | 변함없이 단단한 마음 |
| 8 | 온유 | 호지차 | 배 | 볶아낸 듯 순해진 성품 |
| 9 | 절제 | 말차 | 레몬 | 정갈하고 산뜻한 다스림 |

- 열매마다 찻잎 이름·아이콘·찻물 색, 과일(`fruit`) 이름·아이콘·빛깔, 연결 이미지(`image`), 설명, 오답 귀띔(`hint`), 위로 글귀(`comforts`)가 있습니다.
- 아이콘은 `public/assets/ingredients/`에 있습니다. 색은 `#B4533A`처럼 16진수로 적어 주세요.

### 팽주의 블렌딩 — `src/data/blending.js`
- 이야기에서 **1위 열매는 찻잎, 2위 열매는 과일**로 표현합니다. 순서가 의미를 가지며, 1위와 2위가 같은 열매여도 됩니다. → 정확히 **9 × 9 = 81가지**
- 차 이름 규칙: `{찻잎} {과일}차` (예: 1위 화평, 2위 사랑 → "캐모마일 딸기차")
- **2위가 1위의 20% 미만이면** 2위는 무시하고 같은 열매로 찻잎과 과일을 고릅니다. (`secondRatio: 0.2`)
  - 사랑 50% · 온유 7% → 14% → 사랑 + 사랑 = "홍차 딸기차"
  - 사랑 60% · 온유 13% → 22% → 사랑 + 온유 = "홍차 배차"
- 조언 카드에 덧붙는 문장(`blendLine`, `pureLine`)도 여기서 고칩니다.

### 손님 추가 — `src/data/guests.js`
`GUESTS` 배열에 블록 하나를 복사-붙여넣기 하면 손님 도감과 방문 순서에 바로 반영됩니다.
```javascript
  {
    id: "guest_004",                 // 고유 ID — 절대 중복 금지 (도감 저장 키)
    name: "길을 잃은 여우",
    appearance: "fox_lost.png",      // public/assets/guests/ 안의 그림 파일명
    level: 2,                        // 난이도 1(쉬움) · 2(보통) · 3(어려움)
    story: "손님이 털어놓는 사연",
    required_leaf: 1,                // 찻잎 정답 — 열매 번호 (위 표)
    required_fruit: 3,               // 과일 정답 — 열매 번호 (찻잎과 같아도 됩니다)
    perfect_match_dialogue: "찻잎과 과일이 둘 다 맞았을 때의 대사"
  },
```
- 손님에게도 **찻잎 하나 + 과일 하나**를 블렌딩해 내어 드립니다. (예: 찻잎 1 + 과일 3 → "홍차 복숭아차")
- **난이도(`level`)는 정답이 사연에 얼마나 드러나는지**로 정합니다.

  | level | 사연 쓰는 법 | 예 |
  |---|---|---|
  | 1 쉬움 | 찻잎·과일 이름이 사연에 그대로 나와요 | "엄마가 타 주던 **캐모마일 복숭아차**가 그리워요" |
  | 2 보통 | 재료 칸 아래의 **열매 이름**이 사연에 나와요 | "**오래 참**고 기다렸는데…" → 오래 참음 |
  | 3 어려움 | 이름은 나오지 않아요. 가장 짙은 마음은 찻잎, 그다음 마음은 과일 | "남과 비교하다 마음이 뾰족해져요(온유). 제가 초라하게 느껴지고요(사랑)" |

- **지금 손님 6명:** 쉬움 — 잠 못 드는 아기 양(캐모마일 복숭아차), 생일을 잊힌 고양이(백차 딸기차) / 보통 — 싹을 기다리는 다람쥐(보이차 대추차), 야식을 못 끊는 너구리(말차 대추차) / 어려움 — 지친 직장인 곰(호지차 딸기차), 거절을 못 하는 토끼(녹차 오렌지차). 앞 단계에서 만난 재료가 뒤 단계에서 다시 쓰이도록 짰습니다. (예: 고양이에게서 이름으로 배운 "딸기 = 사랑"을 곰에게는 마음을 읽어 내야 함)
- **방문 순서:** 아직 마음을 데우지 못한 손님 중 **가장 쉬운 단계부터** 찾아옵니다. 같은 단계끼리는 무작위입니다. 모두 데운 뒤에는 직전 손님만 빼고 고르게 다시 들릅니다.
- 쉬움(1) 손님의 사연에 정답 찻잎·과일 이름이 없으면 `npm run check`가 알려 줍니다.
- 배열 순서가 도감 번호(No.001 …) 순서입니다. 쉬운 손님부터 적어 두면 보기 좋습니다.
- 아쉬운 차를 마셨을 때의 대사는 같은 파일의 `MISS_DIALOGUES`에서 경우별로 고칩니다: 찻잎만 맞음(`leafOnly`), 과일만 맞음(`fruitOnly`), 찻잎과 과일의 자리가 바뀜(`swapped`), 둘 다 아쉬움(`none`). `{leaf}`, `{fruit}`는 내어 드린 재료 이름으로 바뀝니다.
- 손님을 추가하거나 빼고 다시 배포해도 기존 유저의 세이브는 깨지지 않습니다. 새 손님은 도감에 잠긴 채로 나오고, 빠진 손님의 기록은 지우지 않고 보관합니다.

### 손님 그림
- 위치는 `public/assets/guests/`이고, 파일명은 `appearance` 값과 똑같이 맞춥니다.
- 권장 규격은 정사각형 PNG, 투명 배경, 768px 이상입니다. 머리부터 가슴까지 보이는 상반신 구도로 그려 주세요. 아래쪽 약 20%는 카운터에 가려집니다.
- 그림이 없으면 게임에서는 실루엣으로 나옵니다.
- **[선택]** 같은 폴더에 `_happy`를 붙인 그림(예: `fox_lost_happy.png`)을 두면, 정답 차를 마신 뒤 그 표정으로 바뀌고 도감에도 그 표정으로 나옵니다.

### 팽주의 학습 문장 — `src/data/trainData.js`
- 고민 문장을 열매 번호별로 적습니다. 문장을 추가하면 다음 실행부터 바로 학습에 반영됩니다. 별도 학습 도구는 필요 없습니다.
- 열매마다 50문장 이상을 권장합니다. 지금은 열매마다 55문장, 모두 495문장입니다.
- 유저가 실제로 쓸 법한 반말·줄임말·다른 표현을 넣을수록 정확해집니다. (예: "싸워서"와 "다투셔서"는 다른 단어로 봅니다)
- "화가 나는 건 아니에요 그냥 외로워요"처럼 부정이 들어간 문장도 섞어 두면 오판이 줄어듭니다.

### 그 밖의 데이터
| 파일 | 내용 |

## 5. 게임 흐름 (`src/hooks/useGameState.js`)

```
TITLE ─[찻집 문 열기]→ (첫 방문이면 INTRO) → Phase 1 손님 맞이 ─정답 후 화면 터치→ Phase 2 찻집 로비
Phase 2 ─[다음 손님 맞이하기]→ Phase 1 (새 손님)
Phase 2 ─[나를 위한 차 끓이기]→ Phase 3 고민 쓰기 + 찻잎·과일 고르기 ─[완성하기]→ Phase 3.5 차 우리는 시간
Phase 3.5 ─광고 시청 / 광고 없음·차단→ Phase 4 팽주의 조언 ─화면 터치→ Phase 2
```
- **첫 화면은 언제나 손님 맞이**입니다. 로비(메인 메뉴)는 첫 손님을 배웅한 뒤부터 열리고, 오늘 밤 맞이한 손님 수와 나를 위한 차 잔 수를 보여 줍니다.
- **Phase 1:** 아래의 **[찻잎 | 과일]** 탭에서 하나씩 고르고 [차 내어주기]를 누릅니다. 둘 다 맞으면 고유 위로 대사와 별조각이 나오고 도감이 해금됩니다.
  - 한쪽만 맞으면 손님이 "호지차 향은 참 좋아요. 그런데 청포도는…"처럼 **어느 쪽이 맞았는지** 알려 줍니다. 맞힌 쪽은 ✓와 함께 고정되고, 아쉬운 쪽 탭으로 넘어갑니다.
  - 찻잎과 과일의 열매가 서로 바뀌었으면 "자리가 바뀐 것 같아요"라고 알려 줍니다. 아쉬웠던 재료에는 ×가 붙고 다시 고를 수 없습니다.
  - 두 번째로 아쉬운 차부터 손님 말 아래에 아직 못 맞힌 쪽(찻잎 먼저)의 귀띔이 나옵니다.
- **조작:** 재료를 고르면 고른 칸을 잠깐 보여 준 뒤 다음 탭으로 넘어갑니다. 재료 칸을 **좌우로 밀어도** 탭이 바뀝니다. 아래 버튼은 빠진 쪽을 알려 줍니다("과일을 골라 주세요"). 대사가 나오는 중에 말풍선이나 화면을 누르면 대사를 끝까지 바로 보여 주고, 다시 누르면 다음으로 넘어갑니다. 차를 내면 고른 찻잎과 과일이 찻잔으로 날아갑니다.
- **PC 키보드:** `1`~`9` 재료 고르기(칸 오른쪽 아래 숫자), `←`/`→` 탭 넘기기, `Enter` 대사 넘기기·아래 버튼. (광고 버튼은 직접 눌러야 합니다)
- **Phase 3:** 고민을 적고 아래의 **[찻잎 | 과일]** 탭에서 하나씩 고릅니다. (찻잎을 고르면 과일 탭으로 넘어갑니다) [완성하기]를 누르는 순간 분석을 미리 끝내 둡니다. 고민 글은 분석 직후 지워지고 어디에도 저장하지 않습니다.
- **Phase 4:** 찻잎과 과일이 **둘 다** 팽주의 블렌딩과 같을 때만 "지금 마음과 딱 맞는 차를 고르셨네요." 그 외에는 "캐모마일 딸기차도 좋지만 홍차 배차는 어떨까요?"처럼 권합니다. 1위 열매의 위로 글귀와 두 재료의 연결 이미지가 함께 나옵니다.
- **저장:** 보유 별조각, 해금 도감, 방문 기록, 설정은 바뀔 때마다 `localStorage`에 자동 저장됩니다. 손상된 기록은 따로 보관하고 새로 시작합니다. 이전 버전 기록은 옮겨 옵니다.

## 6. 기술 구성

| 항목 | 사용 |
|---|---|
| 프레임워크 | React 19 + Vite 8 (라우터 없음) |
| 상태 | **React Context + `useReducer`** (외부 상태 라이브러리 없음) |
| 스타일 | Tailwind CSS 4 (`env(safe-area-inset-*)` → `pt-safe`, `pb-safe` 등) |
| 애니메이션 | Framer Motion — `LazyMotion` + `m`으로 필요한 기능만 |
| NLP | 직접 만든 나이브 베이즈 (`src/utils/naiveBayes.js`) |
| 광고 | Google H5 Games Ads (`src/utils/adService.js`) |
| 사운드 | Web Audio API로 로파이 피아노 BGM과 효과음을 실시간 합성 (음원 파일 없음) |

- JS는 gzip 약 142KB 하나입니다. 팽주의 분석 모듈(학습 문장 포함, 약 11KB)도 함께 묶었습니다. 따로 나누면 새 버전을 배포했을 때, 옛 화면을 열어 둔 유저가 사라진 파일을 받으려다 조언을 못 듣게 되기 때문입니다. 분류기 학습은 앱을 연 뒤 한가할 때 미리 해 둡니다.
- 모바일 최적화: `overscroll-behavior-y: none`, 세로 `100dvh`, 명세의 viewport 메타 태그, iOS 핀치 확대 차단, 고민 입력창 16px(아이폰 자동 확대 방지), 360×640 화면에서도 재료 칸 48px 이상

```
src/
  hooks/useGameState.js     ← 상태 머신 + localStorage 안전 병합
  utils/naiveBayes.js       ← 부정어 전처리 포함 분류기
  utils/adService.js        ← 보상형 광고, 차단·미송출 방어
  data/                     ← 기획 데이터 (guests, ingredients, blending, trainData, scripts, rewards)
  logic/                    ← 데이터 검증, 방문 순서(난이도), 블렌딩, 팽주의 조언, 조사 처리
  screens/phases/           ← Phase 1·2(로비)·3·3.5·4 화면
  components/               ← 상단 바, 재료 패널([찻잎 | 과일] 탭), 밤하늘, 찻집 소품 등
  audio/                    ← 음악·효과음 합성
public/                     ← 그림, og-image.png, about.html, privacy.html, ads.txt, manifest
assets-src/                 ← 그림 원본(SVG)
vite.config.js              ← base 전환, 광고 스니펫, 링크 미리보기, 404.html·CNAME·ads.txt
```

## 7. 팽주의 마음 읽기 — 성능

| 평가 | 결과 |
|---|---|
| 학습 문장 5겹 교차 검증 (짧은 문장) | 1순위 51%, 상위 2개 69% |
| 문체가 다른 새 문장 36개 (반말·신조어) | 1순위 81%, 상위 2개 86% |
| 부정어 사례 ("화가 안 나요" 등) | 5/5 |

- 9가지 중 우연히 맞힐 확률은 11%입니다.
- fastText 방식(글자 n-gram 임베딩)도 같은 데이터로 비교했지만 정확도가 같거나 낮았고, 400KB~900KB의 모델 다운로드가 필요해서 채택하지 않았습니다.
- 틀리는 경우는 대부분 학습 문장에 없는 표현입니다. **학습 문장을 늘리는 것이 가장 효과적인 개선 방법입니다.**
- 단서를 전혀 찾지 못하면, 팽주는 유저가 고른 차를 그대로 존중합니다.

## 8. 알려진 한계
- **광고와 github.io:** AdSense는 `github.io` 하위 주소를 사이트로 승인하지 않고, `ads.txt`는 도메인 루트(`https://도메인/ads.txt`)에 있어야 읽습니다. 지금 주소(`/starlight-tea/`)에서는 광고 없이 동작하며, 광고는 커스텀 도메인으로 옮긴 뒤 켤 수 있습니다.
- **진동:** 안드로이드는 지원합니다. iPhone Safari는 웹 진동을 공식 지원하지 않아 iOS 18 이상에서만 우회 방식으로 일부 동작합니다.
- **소리:** 브라우저 정책상 첫 터치 이후부터 나옵니다. iPhone 무음 모드에서는 나지 않습니다.
- **오프라인:** 지원하지 않습니다. 서비스 워커를 넣지 않았습니다. 홈 화면 추가(manifest)는 됩니다.
- **저장:** 기록은 기기·브라우저마다 따로 저장되며, 브라우저 데이터를 지우면 사라집니다.
